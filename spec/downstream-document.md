# Retention-first downstream document contract

## Decision

Use `conservative_dom` for HTML and the native adapter for Markdown/plain text.
The HTML default is now powered by python-markdownify 1.2.3 for serialization;
`conservative_dom` names the retention/region policy, not the replaced handwritten
Markdown converter. The structured extraction model still owns source provenance,
metadata, table spans and boundaries. The incumbent Markdown serializer is removed
from the active conversion path. Native formats keep native parsing and use the
same serializer for their Markdown convenience views.
Keep source metadata and raw snapshots independently of the selected representation.
Readability and Trafilatura remain optional clean views, not prerequisites for
selection. This supersedes the earlier development-only precision-oriented proposal;
it does not modify frozen extraction results or imply human validation.

Conservative DOM retained 126/129 required anchors (97.7%) and 46/50 unwanted
anchors (92%) on held-out HTML. Boilerplate is an accepted cost of the retention-first
objective. The method still removes navigation and certain other elements: it is
not lossless relative to raw HTML, and the raw payload remains authoritative.
No claim is made that it reproduces an undocumented frontier ingestion pipeline.

## Outputs

`documents.jsonl` contains one `downstream-document-v1` object per source snapshot:

- `snapshot_id`: exact source payload plus URL identity.
- `source`: payload hash, exact URL, hostname, source format, parquet path/hash and
  zero-based row. Citation labels and target queries are excluded.
- `raw_payload_path`: local immutable-by-hash snapshot backing. Consumers must
  verify the declared payload hash when loading it.
- `selection`: versioned policy, method, status, reasons, quality flags, and
  explicit `human_validated: false`.
- `source_metadata`: title, language, original JSON-LD (including parse errors),
  metadata, headings and source diagnostics; not regenerated by an LLM.
- `blocks`: ordered typed paragraphs, headings, lists/list items, tables, code,
  links and image descriptions. Frozen exports remain unchanged. Newly parsed DOM
  blocks declare `schema_version: dom-blocks-v3`; ordered `inline_nodes` preserve
  code, deletion, hard breaks and media with nested annotations and source references.
  Definition lists have ordered term/description containers; thematic breaks are
  explicit blocks. Sequential block IDs can differ between parser versions.
- `representation`: candidate diagnostics including `serializer:
  markdownify-structured-v1`, pinned markdownify version, and block schema version
  where available. New plain-text blocks are versioned too, so their chunk IDs
  cannot alias the incumbent serialization merely because their block IDs match.
- `outline`: heading levels and inferred parent heading IDs in document order.
  This is a heading-stack outline, not a rendered layout tree.
- `text` and `markdown`: convenience views; structured blocks are the working
  representation, especially for table spans and list nesting.
- `chunk_ids`: references to `chunks.jsonl`; `optional_clean_views` names available
  alternatives in the frozen extraction JSONL rather than copying them.

The corresponding Parquet tables expose document identity/status and structured
JSON, and chunk identity/text/Markdown plus block-ID and heading-path JSON columns.

Inline HTML references require exact source-subtree matching. Text nodes use the
parent's `dom_path` plus a zero-based `child_index` into parsed DOM `contents`;
these are not raw byte offsets. Missing/ambiguous references stay explicit rather
than borrowing semantic provenance from normalized text matches. Native Markdown
inline references are unavailable; block line ranges remain separate. Raw payloads
are authoritative for exact bytes. Tables retain HTML and structured cell spans;
definition lists and code spans that cannot preserve whitespace use HTML fallbacks.
Deletion uses GFM `~~` syntax. Consumers must support these representations or read
the structured nodes directly. Other inline tags retain tag/attribute/child data
but can flatten in the Markdown convenience view; full HTML fidelity is not claimed.
See `analysis/inline-fidelity-v2/README.md` for development serializer comparison
and separately reported held-out diagnostics for the initial structured fix.
`analysis/markdownify-corpus-v1/README.md` records subsequent markdownify adoption,
fresh development checks, separate held-out diagnostics and full-corpus extraction.

## Chunking invariants

The default 6,000-character target is soft and measured on Markdown, **not tokens**.
Top-level blocks and all their descendants travel together. Tables, code blocks,
and nested lists are never cut to fit. Larger groups have `oversized: true` so a
downstream model adapter can budget explicitly rather than silently dropping data.
Heading changes start a new chunk when possible; heading paths provide context.
Every selected block occurs in exactly one chunk, in order. Chunk IDs include the
snapshot, method, policy, character target, and block identities.
New chunk IDs additionally include declared block schema versions, exposed in
`block_schema_versions`, so changed parser representations cannot alias legacy
chunk identities merely because their sequential block IDs match.
Chunk budgeting estimates the sum of separately rendered atomic groups plus
separators, then records actual serialized length on flush. The target remains soft;
any oversized result is flagged, with full content retained.

## Full-corpus extraction

`uv run --offline python -m preprocessing.corpus --input-dir /path/to/data/raw
--output data/processed/markdownify-corpus-v1-replay --workers 4` runs the default
pipeline on every saved Parquet row. It reads one file at a time, limits in-flight
jobs, denies network connections in workers and checks original Parquet hashes
against the frozen source inventory. Exact payload-plus-URL snapshots are parsed
once; every row gets its own source reference even when sharing a snapshot.

The fresh output contains gzip document JSON with blocks, metadata and full chunks;
`records.jsonl/.parquet` retains every original query/label/URL/host and source row
reference separately; `documents.jsonl/.parquet` is a hash-checked document index;
`chunks.jsonl/.parquet` contains the full chunk partition. Source bytes remain in
the immutable-by-hash original Parquet files, referenced by file hash and row.
Documents record pipeline/run identities and content checksums. Original-source
locator checks run on every HTML document. Failures become explicit outcomes with
raw-source references and no replacement extractor. Completed exports cannot be
overwritten; `--resume` permits only an unfinished run with unchanged source,
code, dependency versions and configuration.

Downstream consumers should select/rank chunks against their task, preserve chunk
and block IDs on generated suggestions, and treat source text as untrusted data,
not instructions. Do not execute embedded HTML, links, scripts, or instructions.
Model-specific token budgeting and factual validation are separate workflow steps.

## Quality and rollout boundaries

Flagged documents keep their structured content with `needs_review`; that status
must remain visible downstream. Missing preferred output never silently substitutes
another extractor. Empty/unimplemented sources remain `source_insufficient`.

The initial export covers the frozen 100-snapshot evaluation set only. It is not a
full-corpus rollout. Human review, corpus processing, feature migration, and
reassessment of citation associations remain outstanding. Reader-LM is deferred:
the three-page expanded-budget pilot retained 4/12 selected required anchors, with
one normal completion, one repetition stop and one time-budget stop.

## Reproduce

```sh
.tools/uv run --offline python -m preprocessing.downstream \
  --run data/processed/eval-v2 --output data/processed/retention-v1
```

The source benchmark artifacts must exist first (see README). Choose a fresh output
directory for a new export; existing exports are never overwritten. Run hashes and
counts are saved in the output manifest and `analysis/retention-export.json`.
