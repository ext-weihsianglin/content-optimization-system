01 / Objective

Discover a pattern. Apply it to a draft.

What the brief asks for

Analyze HTML and content features associated with stronger citation performance, then build a lightweight tool that generates or improves content for a target query. Deliver a complete example and explain the next steps.

What this dataset can support

Exploratory associations among already-cited pages. “Top” and “bottom” are relative to each hostname. There are no citation counts, exposure denominators, engine identifiers, or observation dates to estimate citation probability or uplift.

Exact wording is a limited matching rule. Unicode normalization, case folding, and whitespace collapse preserve punctuation. Paraphrases may share intent without matching; even identical queries do not establish equivalent exposure or scrape timing.

03 / Broad associations

Alignment and structure survive basic quality filters.

The clean analysis retains 8,687 unique pages, with both labels available in 931 hosts. It excludes conflicting labels, URLs with any failure/sparse/non-HTML flag, and pages below 100 extracted words. Each host is weighted equally in the reported differences.

@@BROAD_TABLE@@

For each host: mean feature value of top pages minus mean of bottom pages. The table reports the median of these host differences. “pp” means percentage points. Query coverage is literal token overlap, not semantic relevance.

Use these as hypotheses, not quotas. Adding 214 words or four headings is not an evidence-backed recipe. Heading count partly reflects length. Similar directions appear on editorial-looking paths, but heading density is weaker there; lists and structured data offer no universal prescription.

Top prompts are shorter and more often include English comparison markers (34.2% versus 23.5%). Different queries, page purposes, languages, shared templates, and residual boilerplate can influence these results.

06 / Brainstorm

A small, inspectable improvement loop.

Starting direction: a query-aware page improvement assistant. Accept a query, existing page, and approved factual material; identify coverage gaps; produce a revised title, outline, and section; explain which observations informed the edits.

Two alternatives

Content blueprint generator: create a source-grounded draft for one query class, with structure conditional on page purpose.

Evidence explorer with generation: inspect matched examples, change filters, choose a hypothesis, and generate a draft that applies it.

What a good demo proves

It completes the evidence-to-draft workflow, addresses the query, traces recommendations to the analysis, and adds no unsupported facts. Citation uplift needs a separate prospective experiment.

Clarify label construction, engine and time coverage, citation counts and exposure, snapshot timing, and the factual sources available for generation.

Methods & provenance

Content analysis uses one page per hostname and URL (fragments removed), picks the longest snapshot where versions differ, and excludes conflicting labels. Text extraction selects the largest main/article/role=main container, falling back to a cleaned body. It is not a rendered-browser view. Quality checks are conservative text heuristics, not verified HTTP status or MIME data.

Exploratory feature tests and multiple-testing adjustments are recorded in the source results. Multiple sensitivity runs and unmeasured confounding limit interpretation. No held-out prediction study or prospective citation experiment has been performed.
