Decision 01

What should projection deliver first?

The same embeddings can support all three paths. Choosing the first outcome keeps the initial implementation focused.

Decision 02

Choose the embedding experiment

Price is not the constraint for this corpus. Use full float vectors first and choose on task evidence. The OpenRouter article is a capability/API shortlist, not a controlled retrieval-quality ranking.

Decision 03

Keep page meaning and section evidence

A single page vector can blur which parts answer the query. The proposed default keeps multiple textual views with traceable source blocks.

ViewInputUse
QueryOriginal associated promptQuery-conditioned alignment; blank prompts remain unavailable.
TitleDocument title and visible H1 as distinguishable inputsTitle alignment without conflating metadata and body text.
OutlineOrdered heading hierarchyTopic organization and broad coverage.
SectionsHeading ancestry + source-derived blocksRelevant supporting passages and section-match distribution.
PageFaithful selected-content serializationOverall semantic context; oversized inputs need an explicit policy.
URL pathHuman-readable path segments, excluding hostname, query string, and fragmentSeparate query–path alignment, such as journal / running shoes.

Split oversized sections at block boundaries, retain nested structure, and serialize tables with their header–cell relationships. Do not silently truncate. Record the contributing block IDs, exact input text, and serializer version.

URL-path representation

For https://stride.example/journal/running-shoes, preserve the raw URL and derive journal / running shoes. Split the path into segments before percent-decoding; convert hyphens and underscores to spaces and retain segment order. Keep the hostname, query parameters, and fragment out of this semantic input.

Embed the derived path independently using document mode and compute query–path similarity in the original vector space. A root-only path has no textual path evidence; malformed URLs receive an explicit unavailable status. Track opaque or numeric segments without silently dropping them. Compare results with and without path features to measure their additional value.

Decision 04

Separate alignment, reduction, and fusion

Alignment features

Compute query–title, query–page, and query–section cosine similarities in the original model space. Retain the strongest supporting sections and the distribution of matches.

Semantic similarity is an alignment signal. It does not establish factual correctness or answer completeness.

Projection features

Use PCA for compact analytical features. Optionally use UMAP for exploration. Preserve original vectors and save fitted transformations.

A 2D cluster is exploratory evidence, not a citation-performance score.

Run artifacts

  • units.parquet: exact inputs, hashes, snapshot/extraction/block references.
  • Vector arrays and an explicit unit-ID index.
  • alignment.parquet: query–snapshot features and supporting section IDs.
  • Fitted projections and their coordinates.
  • Manifest, retry/failure ledger, and configuration.

Store under data/representations/<run_id>/. Cache embeddings independently of projections.

Embed each distinct selected snapshot once and join query-specific results through the citation association table. Preserve multiple snapshots and conflicting labels. Keep prompts, labels, hostname, and URL out of page-content embedding inputs; derive URL-path embeddings through their own view, with a versioned normalizer and cache key.

Validate dimensions, finite values, response indices, and unit accounting. Cache keys include exact input, model, provider, input mode/instruction, dimensions, and serializer version. Bound concurrency and token budgets; resume without duplicate work.

Future image extension

Embedding units carry a modality and optional asset/product reference. Later image vectors join by snapshot/product identity, with explicit missing-image status. Different model spaces stay separate unless a multimodal model explicitly supports shared-space comparison.

The extractor preserves image references but does not fetch assets. Obtaining product-image bytes is a separate next-stage decision.

Proposed milestones

Make the evidence reviewable at each step

  1. Contracts and dry run. Validate upstream joins; inspect deterministic serializers and chunks using structural fixtures.
  2. Model comparison. Stratify a sample by language, page type, length, and extraction quality. Review query–section relevance without treating citation labels as relevance labels.
  3. Frozen corpus run. Choose the model/configuration, batch distinct snapshots, retain failures, and verify resume behavior.
  4. Downstream ablations. Compare structure-only, alignment-only, and combined baselines. Use hostname-held-out splits; fit PCA and learned transforms inside training folds. Audit cross-split duplicate content.
  5. Review and exploration. Inspect successes, misses, model/extractor sensitivities, exclusions, and optional semantic maps.

Report sample sizes and uncertainty. Top/bottom labels are relative within hostname; predictive separation does not prove that an edit increases citation likelihood.
